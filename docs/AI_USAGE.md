# Использование AI-инструментов и проверка результата

Использованы AI-инструменты для помощи в разработке первого прототипа, структуре компонентов, проверке требований, создании плана Instagram API и тест-кейсов. Финальное решение написано с учетом технических ограничений Supabase, Telegram и Meta.

## Что проверено статически

- Корректность JSON workflow и наличие всех ожидаемых узлов/соединений.
- Компиляция TypeScript (`npm run build`) и отсутствие TypeScript ошибок — зафиксировать вывод отдельно.
- Наличие database-level RLS для SELECT, INSERT и UPDATE.
- Отсутствие явных ключей в исходном коде и Git.
- Поведение кнопок, поиск по названию, статусы и настраиваемые категории на уровне кода.

## Что нужно проверить в живой среде

- OAuth/вход/выход и подтверждение email с конкретными настройками Supabase.
- Изоляция двух пользователей и прямые запросы к PostgREST.
- Webhook Telegram в реальном боте, 2/5/9 кнопок, смена услуг и обработка callback.
- Доступность задеплоенной веб-страницы на мобильном экране.
- Токены и метрики Meta: согласно ТЗ задача 2 является только исследованием.

## Решённые технические риски

- RLS не просто фильтрует строки на фронтенде — проверяет `auth.uid()` внутри БД.
- Во время сохранения `saveInFlight` блокирует повторную отправку до завершения первого запроса.
- Supabase ошибки отображаются пользователю, а успех появляется только после ответа БД.
- Telegram возвращает ID в callback и узнаёт актуальное имя услуги из таблицы.
- Запрещено включать service_role или реальные токены в репозиторий.

## Известные ограничения

Без личного Supabase project и Telegram BotFather token невозможно честно заявить end-to-end испытания. Веб-приложение в таком случае показывает экран настройки; это не рабочий тестовый backend. Клиентский in-flight guard предотвращает двойной клик в одном окне; distributed idempotency при сетевых повторах выходит за рамки ТЗ.

## Дополнительная проверка реального приложения (5 ноября 2026)

На опубликованном сайте с настоящим Supabase выполнены 10 браузерных сценариев через Chromium: вход под двумя аккаунтами, пустая форма, двойное нажатие при создании, сохранение/редактирование названия, описания, категории и статуса, совместный поиск и фильтр, повторная загрузка, выход, RLS-изоляция пользователя B и экран 360 px. Все 10 прошли.

Отдельный тест при ширине **320 px** подтвердил отсутствие горизонтального переполнения. При временном отключении сети выяснилось, что Supabase возвращает объект ошибки, который UI показывал как `[object Object]`. Обработку ошибок улучшили: сообщения о сетевом сбое, неправильном пароле, неподтверждённом email и лимите запросов теперь переводятся в понятный текст. После восстановления сети форма сохраняется повторно без потери введённых полей.

**Известная конфигурационная проблема:** в Supabase Auth пока требуется указать Site URL и разрешённый Redirect URL опубликованного GitHub Pages. Без этого подтверждение email перенаправляет на стандартный localhost. Это не ошибка RLS или браузерного входа; переход требует настройки проекта в Supabase Dashboard.
